# VulnGym T2：报告到可复核数据

2026-09-10 v3 | 主T2，辅T1 | 可运行工程候选，质量尚未全部验收

## 1. 交验的产品是什么

主产品是CLI与JSONL批处理：把获准的真实报告、公告/patch资料及固定Git源码，整理成完整VulnGym Entry候选，附来源、定位及T1检查。无需Web界面。导师接受有证据、有补充动作的不确定，不接受无依据的确定标注。

当前支持单一GHSA、可解析修复提交及唯一父提交、显式声明源码文件。资料包、本地仓库映射和Git对象需预先准备；不是任意URL/PDF一键抓取器，不执行目标项目。唯一父提交不自动证明该代码对应全部受影响版本。

## 2. 生产路径及边界

批准的资料 → 有界候选与源码窗口 → 模型规划、语义选择、自检 → 完整候选或具体弃答 → 完整候选交给真实本地T1 → 混合交接包与复核清单。

DeepSeek V4 Pro负责结构化选择与自检。本地控制器负责候选ID、代码位置、摘要、schema、次数和预算。候选change_kind、窗口省略及未验证角色均显式保留；源码存在、邻近或被patch修改，不能单独证明角色和关系。

T1提供结构、位置、版本及角色等字段检查，不能将“检查未实现”当正确。模型自检亦不是独立评审。缺证据保留manual_review；代码、原T1、verify=0和trace不为提高通过率而改写。

## 3. 结果如何分别记账

完整候选：全部必填字段齐备，可与T1报告交评审，仍不是已验证正确的数据。弃答：保留具体字段、证据、原因和下一动作，但不算完整Entry。执行异常：超时、拒绝、截断、格式或预算问题单独记账，不能算正常语义弃答。

CLI退出0只代表处理按契约完成；存在模型调用问题则退出1。entries_written只统计finalized，不能用它代替候选计数。混合handoff保留候选与弃答，不冒充严格完整export或人工签收。
