# VulnGym T2：报告到可复核数据

2026-09-09 | 主交验 T2，辅助 T1 | 工程可交接，质量验证仍部分完成

## 1. 产品和适用范围

目标是帮助研究者把真实报告整理成完整 VulnGym Entry。工具读取批准的公告/patch资料及固定Git源码，生成带来源和定位的候选；缺证据时保留明确的复核记录。主入口是CLI和JSONL批处理，不要求Web界面。

当前支持单一GHSA、可解析的修复提交及唯一父提交、显式声明的源码路径。报告、资料包、本地仓库映射和Git对象需要事先准备。工具不是任意URL/PDF一键抓取器，也不执行目标项目；唯一父提交不自动等于所有受影响版本的充分证明。

## 2. 实际流程

公告与版本资料 → 有界候选收集 → 模型规划 → 语义选择 → 结构自检与模型自检 → 完整候选或defer → 辅助T1 → 交接与复核。

DeepSeek V4 Pro负责结构化选择和自检；本地控制器负责文件/Git读取、候选身份、预算、schema与证据绑定。候选ID与代码位置核对限制无依据输出，但不单独证明入口角色或调用联系。源码窗口存在明确截断和遗漏标记，不把距离近或引用存在当成语义证明。

T1真实检查完整候选，能提供结构、位置、版本等辅助证据；部分角色及trace检查仍保守待定。只有可靠的建议才能进入有限字段修正，修正必须保留前后记录。此次交验不以所有任务finalized为目标。

## 3. 三类输出必须分清

完整候选：有全部必填字段，可与T1报告一起交给评审。机器数据verify始终为0；有完整候选不代表已正确或已由人工验证。

语义弃答：模型基于当前资料不能作出可靠选择，保留具体原因、证据和下一步复核动作。人工允许不确定，但不能以全部弃答代替数据生产能力。

执行未完成：超时、服务拒绝、预算或格式异常。新CLI分别显示候选数、T1报告数和模型调用问题；存在模型调用问题时退出1，而非仅因终态已保存就显示ok。旧回放格式和历史结果不改写。

真实模型开发两例：既有版本产出1份完整候选及真实T1 uncertain报告，另一例在自检阶段defer。该候选单独九维自评为6支持、1合理替代、2待定；不能与历史12条合成13条盲测。版本关系与空trace的完整性仍有待核实。

已修复候选/入口提名局限、整行代码截断、语义上下文未投递，以及不具体的自检弃答。旧侧候选、callable与有界窗口仍是待判材料，不直接升级为答案。

# 交付、复现与截止前安排

## 7. 接收方如何使用

解压交接包，先运行包内verify_delivery.py校验文件。进入source后执行 python -B -m vulngym_agent.t2_production_cli --help；核心CLI使用Python标准库，已在Python 3.13.12验证，不必安装模型SDK。可选开发依赖和正式签名工程另列。

结果演示命令见包内README。演示读取已核验的真实历史候选、弃答与超时记录，不调用模型、不要求key、不执行目标源码。它是明确标识的已有结果讲解，不是现场新报告生成，也不是独立质量评审。

实际生产需配置获准任务、资料和仓库映射，使用新输出目录。示例参数为--max-records 2 --max-llm-calls 3 --max-repair-iterations 0 --progress。模型服务另需有效凭证、资料发送授权与费用上限；一次请求超时的计费不能假设为0。

可显式设置VULNGYM_DEEPSEEK_TIMEOUT_SECONDS=300，默认仍为120。增加等待不增加自动请求数，也不保证成功；新配置会改变后端配置身份，应登记新版本/运行目录，不能借此重写旧结果。所有此前已宣布结束使用的key不再复用。

## 8. 截止前只保留三项优先工作

第一优先：在明确预算、请求数和等待上限的新授权运行中取得可用语义结果；再逐字段评价完整候选或核对真实弃答理由。不能保证下一次调用成功，也不能用改状态替代能力改进。

第二优先：交付可运行源码、README、完整候选与T1数据、分组评价、失败记录、三页设计说明及真实开发记录。机器输出、后补证据与人工修订分开；未完项明确注明。
