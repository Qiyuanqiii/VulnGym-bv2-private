# T2：当前产品主线

2026-09-10。重新阅读用户修订版考题第6—10页及导师完整会议转写后更新。本文管下一步工作；旧运行结果照原样保留，不重新计算成绩。

## 做什么

让研究者把真实公告及可用仓库资料交给系统，得到可用的 VulnGym 数据和明确的待审说明。主 T2，T1 是辅助；不是建设数据签收平台，也不是修复目标项目的代码。

考题明确 `trace` 可以为空，机器 `verify=0`；不允许用编造内容凑齐字段。导师强调选一道做精、自己选择有代表性的资料、说明怎样评价和改进系统，保留真实 AI 编程与调试过程。原表格分数、行号±5、固定样例数量不是最终评判标准。

尤其注意：导师希望考虑资料不完整的真实应用报告，不只挑有完善补丁和链路的 Linux 样本。当前程序依赖单一GHSA、能确认的修复提交/父提交及显式源码范围，这是已有实现限制，不是导师要求输入必须如此。

## 现在怎么推进

1. 让现有 CLI 的结果直接可用：完整 T2 候选单独输出，不要求 T1 已经 finalized；有真实报告则一起输出，无报告则明确尚未验证。没有完整候选的任务仍单列弃答，不冒充 Entry。
2. 下一处核心改进是按需补上下文：模型指出缺少哪个符号/调用方后，在允许的源码范围内补读一次，再判断；无权限、无证据或仍不明确则待审。复用已有检索，先不安装新框架或建设全仓库调用图。
3. 在一组获准的报告上比较少量模型/配置。分开记录完整产出、明确错误、证据不足、调用失败、耗时和实际用量。开发时看过的资料不得叫新增盲测；比较尚未执行，不虚构成绩。
4. 选出可以提交的配置和真实案例，交源码、输出、简短设计、自评及 AI 协作过程。已有材料可直接复用，不因每次修改重做 ZIP/PDF/视频。

只做本次改动直接需要的检查和实际用例，不默认跑全量回归、不追加封存/回放/签收项目。仍保留必要的 schema、源码真实性、费用限制和不覆盖旧数据要求。GUI/TUI暂后排。

## 同类实现，取其具体方法

以下是官方项目/原论文，不是使用其答案替代我们生成数据；没有下载其标注数据。

| 项目 | 实际实现 | 可借鉴的部分及限制 |
| --- | --- | --- |
| [CVEfixes](https://github.com/secureIT-project/CVEfixes) | 自动收集并关联CVE、仓库、修复提交、文件及函数，保存前后源码 | 自动准备基础事实。修复关联本身不证明入口/关键操作语义 |
| [ReposVul](https://arxiv.org/html/2401.13169v1) | 公告/补丁收集，Tree-sitter提取函数，LLM与静态工具判断补丁相关性，再抽取调用依赖 | 提供完整相关函数和必要调用上下文；它不是直接产出本题EP/CO/trace的成品 |
| [Vulnhuntr](https://github.com/protectai/vulnhuntr/blob/main/vulnhuntr/__main__.py) | 结构化请求额外符号上下文，补读并去重，无新增内容或达到轮数就停止 | 借鉴“缺证据→补读→再判断”。它面向发现、且Python限定，不能直接搬到所有语言 |
| [Serena](https://github.com/oraios/serena/blob/main/src/serena/tools/symbol_tools.py) / [Aider](https://aider.chat/docs/repomap.html) | 符号/引用查询，或按预算先提供仓库符号地图，再展开正文 | 借鉴渐进检索，不把引用搜索结果直接当已证实链路；暂不为此迁移框架 |
| [PrimeVul](https://github.com/DLVulDet/PrimeVul) | 基于规则缩小标注范围、清洗重复、组织模型评价数据 | 借鉴分组评价；不能通过筛掉难题后宣称整体效果更好 |

## 不混淆三件事

- 原始需求：真实报告到有用的数据，允许有依据的人工复核。
- 已完成：现有受限CLI、真实T2→T1样例和工程交付包；最新同两题1份完整候选、1份弃答。
- 尚未完成：按需补读机制、代表性新报告的稳定产出与模型对比。直接结果输出只是易用性改进，不增加模型样本或准确率。

新模型实跑另需有效凭证、允许发送的输入范围及费用授权。不得复用已宣布结束使用的旧key。所有新结果和临时文件放D盘；主工作区只读，私人远端约束不变。
