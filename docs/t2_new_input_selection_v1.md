## 固定资料规则

1. 通过普通GitHub CLI读取全局公开advisory，保存完整响应摘要及规范化输入；不读取评测答案。模型输入使用开头Summary段（无此标题则使用正文）、最长2000字符，并明确标注摘录边界；原文中不必要的可执行示例不进入模型输入。
2. 以公告原始commit引用核对唯一修复及其直接单父提交。将该父提交作为待分析的修复前工作快照，不把父子关系单独称为受影响版本的语义证明。
3. patch由固定父/修复的Git diff产生。source_paths包括这次diff中旧侧存在的生产源文件；排除测试、文档等，规则不参考EP/CO答案。
4. entry_symbols为空，critical_mode=auto；不填充输出标题、分类、位置、trace或人工verify。
5. 固定输入文件字节、Git对象、模型配置、代码版本与脚本摘要，正式运行前再次读回。失败不改写历史，不盲重跑。
