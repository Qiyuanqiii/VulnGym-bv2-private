## 已确认的问题与修正

1. **未评价与否定含义不清。** 采集器一直输出 `call_relationship_verified=false`，并不检查关系真伪；最新两份模型弃答却把该标记列入理由。这证明理由引用了标记，不能单凭此断定全部弃答都是误判。保留 False，增加明确的 `not_assessed` 来源说明；提示词 `t2-json-v5` 要求根据实际代码/公告评价，不能仅凭“无人预先验证”选择或弃答。缺连接、缺范围、矛盾仍须保守记录，不强迫输出。
2. **邻近锚点之间仍有窗口缺口。** 原实现围绕每个候选取前后24行；大型 Python 函数只给局部范围。现在允许同文件、相反角色的近邻锚点共用一段连续源码，前提是整个锚点区间放得进原3000字符上限。Python AST 已知函数边界时不跨边界配对；其他语言不声称解析出函数或调用图。配对只用于选取上下文，不证明语义关系。
3. **窗口重叠浪费配额。** 已有完整行不重复发送；新窗口只裁掉与旧窗口重叠的边缘，不能裁掉本次主锚点。部分截断的长行不视作可复用的完整覆盖。候选目录、ID、语义输出契约、T1、`verify=0`、弃答和正式导出规则均不放宽。

源码仍仅来自已声明文件的固定 Git 对象。保持每题最多8文件、12窗口、16000源码字符，每窗口3000字符；不额外寻找目标文件，不执行目标代码，无自动重试。
