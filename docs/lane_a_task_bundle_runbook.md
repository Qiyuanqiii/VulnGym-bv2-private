# Lane A task-bundle control plane

This control plane deterministically prepares answer-free public benchmark rows for the existing T2 `RunTask` contract version 2. It does not run T2 and does not assign correctness.

## Trust boundary

Two separately reviewed, immutable JSONL inputs are required. Each line must be canonical UTF-8 JSON followed by LF. Duplicate JSON keys, CRLF, reordered rows, duplicate identities, extra keys, and changed bytes are rejected.

The public task file has exactly these keys:

```json
{"commit":"0123456789012345678901234567890123456789","instruction_id":"vulngym-whitebox-locate-v1","repo_url":"https://github.com/example/repo","split":"test","task_id":"VG-TEST-00000000000000000001"}
```

It is the sole authority for `task_id`, `repo_url`, `commit`, `split`, and `instruction_id`.

The separately cleared advisory assignment file has exactly these keys:

```json
{"entry_id":"entry-00001","hints":{"critical_mode":"auto","entry_symbols":[],"fix_commits":[],"project":"example","source_paths":["src/example.py"]},"package":{"advisory":"advisory/item.json","patches":[],"references":[]},"report_id":"GHSA-AAAA-BBBB-CCCC","task_id":"VG-TEST-00000000000000000001"}
```

Assignment `task_id` must equal the public task at the same ordinal. Assignment data cannot contain source identity overrides, Entry answer fields, absolute paths, or private/gold/source-map/selection-lock path segments. All package and source paths are repository-relative.

Obtain the two semantic digests, two exact-wire digests, and row count in a separate trusted review step. Production `build` never derives or accepts replacement pins from the output directory.

## Build

```powershell
python -B -m vulngym_agent.lane_a_task_bundle_cli build `
  --public-tasks-file D:\cleared\test.jsonl `
  --assignments-file D:\cleared\test-assignments.jsonl `
  --expected-public-tasks-sha256 PUBLIC_SEMANTIC_SHA256 `
  --expected-public-tasks-wire-sha256 PUBLIC_WIRE_SHA256 `
  --expected-assignments-sha256 ASSIGNMENT_SEMANTIC_SHA256 `
  --expected-assignments-wire-sha256 ASSIGNMENT_WIRE_SHA256 `
  --expected-task-count 20 `
  --protected-path D:\cleared `
  --output-dir D:\lane-a\test-task-bundle
```

Publication uses a private same-parent staging directory, exact readback, and an atomic no-replace rename. On POSIX, the parent and staging directory are pinned by descriptors; file creation, readback, rename, and directory fsync are descriptor-relative with no-follow semantics. Trusted directory identities are compared with the output ancestor chain so bind-mount aliases cannot bypass the textual overlap check. The second isolation check returns the exact output-parent identity chain to the publisher, which must bind that same identity before it creates the staging directory. An existing output is never overwritten. Successful stdout is one canonical, path-free JSON object.

Failed publications never automatically delete a staging directory. This avoids an unavoidable check-to-unlink name race with another actor running under the same account and preserves the original error or interruption classification. Operators must inspect and dispose of retained staging directories explicitly rather than deleting them blindly.

The output contains only:

- `run_tasks.jsonl`: ordered T2 `RunTask` objects whose `inputs.contract_version` is 2 and whose `expected_vulnerable_commit` exactly equals the corresponding public `commit`.
- `manifest.json`: both input semantic and wire digests, ordered per-task public/assignment/run-task digests, output byte count and digest, split, count, and bundle digest.

## Independent verification

Verification requires the original two pinned inputs and compares regenerated bytes with the published bytes:

```powershell
python -B -m vulngym_agent.lane_a_task_bundle_cli verify `
  --public-tasks-file D:\cleared\test.jsonl `
  --assignments-file D:\cleared\test-assignments.jsonl `
  --expected-public-tasks-sha256 PUBLIC_SEMANTIC_SHA256 `
  --expected-public-tasks-wire-sha256 PUBLIC_WIRE_SHA256 `
  --expected-assignments-sha256 ASSIGNMENT_SEMANTIC_SHA256 `
  --expected-assignments-wire-sha256 ASSIGNMENT_WIRE_SHA256 `
  --expected-task-count 20 `
  --bundle-dir D:\lane-a\test-task-bundle `
  --expected-bundle-sha256 BUNDLE_SHA256 `
  --expected-manifest-wire-sha256 MANIFEST_WIRE_SHA256
```

Exit code `0` means verified, `2` means rejected before a confirmed publication, and `11` means publication state may require readback before retry. For `build`, a failure to encode, write, or flush the success summary after publication also returns `11`; such failures can never be reported as pre-publication rejection. Never delete or overwrite an output after exit `11`; verify its pinned digest first.
